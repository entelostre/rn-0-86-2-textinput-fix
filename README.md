# rn-0-86-2-textinput-fix

React Native **0.86.2** Android artifacts, rebuilt from source with one patch applied,
published in Maven repository layout so Gradle can consume them directly.

Everything here is React Native (MIT, © Meta Platforms) plus the patch below.
No other code is included. See `LICENSE-react-native`.

## Why this exists

React Native's Android `TextInput` retains the previous `AndroidTextInputState` via
`fragment.parentShadowView.state`. Over a long run of continuous value updates this forms an
unbounded chain that is destroyed recursively, overflowing the native stack (SIGSEGV).

Upstream fixed the shared/iOS path in 0.86 (`shadowViewFromShadowNode`, RN #55719) but **not**
the Android path (`AndroidTextInputShadowNode.cpp`), which is still unfixed in 0.86.2.

A `patch-package` patch alone does **not** solve this on Android: the app resolves the prebuilt
`com.facebook.react:react-android` AAR from Maven, so patched sources under `node_modules` are
never compiled. Hence these rebuilt artifacts.

## Contents

Maven layout under `com/facebook/react/react-android/0.86.2/`:

| File | Notes |
| --- | --- |
| `react-android-0.86.2-release.aar` | used by release builds |
| `react-android-0.86.2-debug.aar` | used by debug builds |
| `react-android-0.86.2.pom` | carries the 20 transitive dependencies |
| `react-android-0.86.2.module` | Gradle metadata; selects debug/release variant |
| `*.sha256` etc. | checksums generated by Gradle |

Hermes is **not** included and is unchanged: it is a `compileOnly` dependency of
ReactAndroid, so it is absent from the POM and resolves normally from Maven Central as
`com.facebook.hermes:hermes-android`.

## The patch

Three hunks in
`ReactCommon/react/renderer/components/textinput/platform/android/react/renderer/components/androidtextinput/AndroidTextInputShadowNode.cpp`:

1. `clearFragmentBackReferences()` — nulls `parentShadowView.props`/`.state` on every fragment
   before the AttributedString is stored back into `AndroidTextInputState`.
2. The same nulling on the tree fragment in `getAttributedString()`.
3. A build marker (see below).

## Verifying the patch is present

The helper is `static` and release builds inline it under `-O2 -flto=thin`, so **its symbol is
absent from the shipped library and cannot be used to check for the patch.** A string constant is
embedded instead, which survives both stripping and inlining:

```sh
unzip -p react-android-0.86.2-release.aar jni/arm64-v8a/libreactnative.so \
  | strings | grep kinvent-textinput
# expected: kinvent-textinput-v1
```

Run the same check against a built APK to prove a shipped binary contains the patch.

## Consuming from Gradle

```groovy
allprojects {
    repositories {
        maven { url = uri("<path to the unpacked tree>") }  // declare before mavenCentral()
        mavenCentral()
    }
}
```

Coordinates are identical to upstream (`com.facebook.react:react-android:0.86.2`), so nothing
else changes — but note this **shadows** the official artifact. That is deliberate: React
Native's Gradle plugin force-pins that exact coordinate.

## How it was built

```sh
# with patches/react-native+0.86.2.patch applied to node_modules/react-native
cd apps/physio/android
./gradlew :react-native:packages:react-native:ReactAndroid:\
publishReleasePublicationToMavenTempLocalRepository
# output: /tmp/maven-local
```

Toolchain: JDK 17, Node 22.23.1, NDK 27.1.12297006, CMake 3.30.5, Gradle 9.3.1.
ABIs: arm64-v8a, armeabi-v7a, x86, x86_64.

Build paths are remapped to `/react-native` via `-ffile-prefix-map`, so no build-machine
paths are embedded. Byte-for-byte reproducibility is **unverified** (zip timestamps and entry
ordering may still differ) — verify with the marker check above, not by comparing hashes.

## Rebuilding for a new RN version

Always on a dev machine, never in CI. Needs ~25 GB free and ~1h45m cold.

1. In the app's `apps/physio/android/settings.gradle`, temporarily restore the composite build
   (it is removed there, because the app normally consumes this artifact):
   ```groovy
   includeBuild('../../../node_modules/react-native') {
       dependencySubstitution {
           substitute(module("com.facebook.react:react-android")).using(project(":packages:react-native:ReactAndroid"))
           substitute(module("com.facebook.react:react-native")).using(project(":packages:react-native:ReactAndroid"))
           substitute(module("com.facebook.react:hermes-android")).using(project(":packages:react-native:ReactAndroid:hermes-engine"))
           substitute(module("com.facebook.react:hermes-engine")).using(project(":packages:react-native:ReactAndroid:hermes-engine"))
       }
   }
   ```
2. Check `patches/react-native+<version>.patch` still applies (two files: the TextInput fix +
   marker, and the `-ffile-prefix-map` cppFlags hunk). Bump the marker string if the fix changes.
3. Build and publish:
   ```sh
   cd apps/physio/android
   JAVA_HOME=<jdk17> ANDROID_HOME=<sdk> ./gradlew \
     :react-native:packages:react-native:ReactAndroid:publishReleasePublicationToMavenTempLocalRepository
   # -> /tmp/maven-local
   ```
4. Verify the marker is in the release AAR and that no `/Users/` paths remain.
5. `cd /tmp/maven-local && zip -r -0 <name>.zip com`, `shasum -a 256`, then `gh release create`.
6. Update `rnPatchedRelease` / `rnPatchedSha256` / `rnPatchedUrl` in the app's `settings.gradle`
   and **revert step 1**.

If patch-package fails while regenerating the patch, move the build leftovers aside first
(`ReactAndroid/.cxx`, `ReactAndroid/build`, `hermes-engine/{.cxx,build}`, `sdks/hermes`,
`sdks/download`, `.gradle`) and strip any `.gradle/**` sections from the generated patch.
